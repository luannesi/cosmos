COSMOS — pacote portátil
=========================

COSMOS é o sistema: a camada CHAOS (onde o conhecimento mora),
a camada ORDER (o que executa) e o binding que realiza as duas
nesta máquina. Este pacote traz as ferramentas; o Git traz o
conteúdo.

Windows:  dê um duplo clique em  INICIAR.cmd
Linux:    abra um terminal aqui e rode  ./iniciar.sh

O assistente pergunta o que você quer fazer:

  [1] Conectar a um repositório Git que já tem o seu conteúdo
  [2] Criar um repositório novo do zero
  [3] Criar um repositório novo e automatizar tudo (Onboarding,
      chaves, push e worker no logon — Partes 1 a 6)
  [4] Só preparar o ambiente, sem repositório

As opções [1], [2] e [4] seguem o limite deliberado abaixo. A
opção [3] é a exceção, explícita: quem escolhe "automatizar tudo"
está pedindo pra sair desse limite.

O que este pacote NÃO faz, por decisão de desenho (opções 1, 2 e 4):

  - não instala nada fora desta pasta;
  - não guarda nenhuma credencial sua;
  - não traz chave de assinatura alguma: elas nascem
    na sua máquina, no Onboarding, e a privada nunca
    entra em repositório nenhum;
  - não se atualiza sozinho;
  - não "conserta" divergência de versão.

Nas opções [1], [2] e [4], duas coisas continuam sendo instalação
sua, e o assistente imprime os comandos prontos no fim: o Claude
Code (uma linha, sem administrador) e o registro do worker no
logon. Na opção [3], só o Claude Code continua manual — Onboarding,
chaves, push e worker são automatizados por bootstrap_cosmos.py,
que nunca vê frase-secreta nem credencial: essas continuam indo
direto pro prompt do terminal (ssh-keygen/git commit).

Pacotes adicionais opcionais (Ollama e ai-memory)
--------------------------------------------------

Nenhum dos dois é necessário: o COSMOS funciona inteiro sem os dois
(é um teste de aceitação formal da especificação — AT-34, para o
ai-memory — e a Parte 4 do tutorial explica o que fica bloqueado
sem GPU/Ollama). Por isso os dois são OPT-IN, ao contrário do resto
deste pacote:

  - Ollama (modelos locais): quem monta o pacote decide incluir com
    `montar-pacote.ps1 -ComOllama` (ou `montar-pacote.sh
    --com-ollama`). Sozinho, sem CUDA, fica em torno de 200 MB;
    com `-OllamaComCuda` (aceleração NVIDIA), passa de 1,4 GB — por
    isso não vem por padrão, mesmo sendo opt-in. Modelos em si
    continuam de fora sempre: são gigabytes que só fazem sentido
    baixar na máquina de destino, e essa etapa é sempre uma
    pergunta, nunca automática.

  - ai-memory (camada episódica, opcional — CHAOS §4.2): quem monta
    o pacote decide incluir com `-ComAiMemory` / `--com-ai-memory`.
    Pequeno (~18-40 MB), verificado por sha256 contra o publicado
    pelo projeto. O caminho nativo embutido no pacote é rotulado
    "experimental" pelo próprio projeto no Windows — Docker
    continua sendo a via recomendada (Parte 1.5 do tutorial) e
    nunca é automatizado por este pacote, porque gera um token de
    autenticação, que é exatamente o tipo de credencial que este
    pacote promete nunca guardar.

Se quem montou o pacote incluiu um dos dois (ou os dois), o
assistente pergunta, no final da instalação, se você quer ativá-los
agora — sempre uma pergunta, nunca silencioso, e nunca baixa modelo
do Ollama sem confirmar. Se nenhum dos dois foi incluído, o
assistente avisa e mostra como adicionar depois.
